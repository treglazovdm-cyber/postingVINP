# VINP studio — контент-план

Первая локальная версия планировщика для ВКонтакте и Telegram.
YouTube и Instagram отложены на следующие этапы.
Русский интерфейс, выбор площадок, текст, один медиафайл до 100 МБ на запись,
расписание и отмена записей. Время вводится в часовом поясе устройства, хранится в UTC.

Telegram поддерживает отправку по расписанию: текст, фото JPG/PNG, видео MP4,
остальные файлы — документом. ВК ещё не подключён. У каждой площадки сохраняются
статус и ID сообщения Telegram; общий статус может быть «Отправлено частично».
Заголовок — внутреннее название записи; в канал уходит текст, а если он пуст — заголовок.
Текст до 4096 символов UTF-16, подпись к файлу до 1024; фото до 10 МБ,
остальные файлы до 49 МБ. Ограничения форматов Telegram могут отклонить отдельный файл.

## Подключение Telegram на VPS

1. Создайте бота командой `/newbot` в официальном `@BotFather`.
2. Создайте отдельный тестовый канал. Добавьте бота администратором с правом
   публикации сообщений. Для начала удобен публичный канал с именем `@имя_канала`.
3. Откройте приложение через SSH-туннель. В блоке «Настройки Telegram» введите
   токен из BotFather и `@имя_канала` (или числовой ID закрытого канала вида `-100…`).
4. Нажмите «Сохранить настройки», затем «Проверить подключение Telegram».
   Проверка использует getMe/getChatMember и не публикует сообщения.
5. Создайте запись только для Telegram со временем через 2 минуты. Дождитесь её
   появления в канале и статуса «Отправлено» с ID сообщения в интерфейсе.

Токен вводится скрыто, после сохранения поле очищается; API возвращает только признак
наличия токена и адрес канала. При изменении канала оставьте токен пустым, чтобы
сохранить текущий. Изменения действуют без перезапуска приложения.
Настройки хранятся в `DATA_DIR/telegram-settings.json` атомарно с правами `0600`.
Файл содержит токен в открытом виде: защищайте каталог данных и резервные копии.
Он не входит в Git и Docker-образ. Авторизации в сервисе пока нет — используйте
форму только через SSH-туннель, не открывайте приложение в публичный интернет.

Совместимость: если настройки через интерфейс ещё не сохранены, используются
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из переменных процесса (для Compose — `.env`).
Сохранённые в интерфейсе значения имеют приоритет. Если токен задан через окружение,
его можно не вводить повторно: сохраните только канал. Не показывайте токен в чате.
Перед настройкой отмените ненужные старые запланированные записи:
просроченные записи со статусом «Запланировано» отправляются при запуске или после
подключения аккаунта. Старые записи «Нужны аккаунты» автоматически не возобновляются.

Автоматические повторные попытки пока отключены, включая 429 и ошибки сети.
При сбое соединения или перезапуске во время отправки сообщение могло быть доставлено:
сначала проверьте канал, затем при необходимости создайте новую запись.
Уже отправленные сообщения кнопкой отмены не удаляются.
Токен не возвращается API и не включается в архив/образ. Для VPS нужен HTTPS-доступ
к `api.telegram.org`. Из облачной среды не проверялась реальная доставка: нужен ваш бот.
Локальный `python app.py` не читает `.env`; он использует переменные процесса.

## Локальный запуск

Требуется Python 3.12 или новее, внешних зависимостей нет.

```sh
python app.py
```

Откройте в браузере адрес с хостом `127.0.0.1` и портом `8000`.
Настройки: `HOST` (по умолчанию `127.0.0.1`), `PORT` (`8000`),
`DATA_DIR` (по умолчанию `data` в репозитории).
Каталог данных создаётся автоматически. SQLite и загруженные файлы сохраняются между
перезапусками. Просроченные записи обрабатываются при старте; проверка расписания каждые 5 секунд.

```sh
python -m unittest discover -s tests -v
```

## Docker и будущий TrueNAS

```sh
mkdir -p data
# Контейнер использует UID/GID 1000:1000 — каталог должен быть доступен ему для записи.
docker compose up --build -d
docker compose logs planner
docker compose down
```

Чтобы перенести данные на TrueNAS, остановите сервис, скопируйте весь каталог данных
(базу и media), задайте `VINP_DATA_DIR` путём к отдельному dataset и права для UID/GID
1000:1000. Затем запустите сервис. Базу SQLite размещайте на локальном dataset TrueNAS,
не на SMB/NFS-ресурсе. Это инструкция для будущего переноса; на настоящем NAS пока не проверялась.

Текущая версия однопользовательская, без авторизации и TLS: запускать только локально.
Порт Compose привязан к loopback. Перед доступом с телефона или публикацией в интернет
потребуются авторизация, HTTPS и сервер для production. Не открывайте порт напрямую.
Файлы хранятся по внутренним идентификаторам; исходные имена сохраняются в базе.
Автоматическое чтение существующей медиатеки NAS пока не реализовано — файлы загружаются через интерфейс.

Для резервной копии остановите приложение и скопируйте весь `DATA_DIR`.
Не храните токены в репозитории или медиафайлах.
